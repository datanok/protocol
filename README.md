# Protocol

A personal life OS. Build structured plans across workout, skill, study, and nutrition modules — generated by AI or crafted manually — then commit to them daily.

## Stack

- **Next.js 15** (App Router) — React Server Components + Server Actions
- **Supabase** — Postgres, Auth, Row Level Security, Storage
- **Gemini API** — plan generation
- **TanStack Query** — client-side caching and invalidation
- **Tailwind v4** — `@theme` in `globals.css`, no config file

## Getting Started

```bash
npm install
npm run dev
```

Create a `.env.local` at the project root:

```
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
GEMINI_API_KEY=
ANTHROPIC_API_KEY=
```

## Plan Schema

Plans are stored as `plan_json: jsonb` in the `plans` table. The root type is `AestheticOSPlan`:

```ts
{
  metadata: { goal, level, version: 2, planType },
  habits:   [{ id, name, category }],
  modules:  Array<WorkoutModule | SkillModule | StudyModule | NutritionModule>
}
```

`modules` is a discriminated union on `type`. Always narrow before accessing `data`:

```ts
if (mod.type === "workout") {
  const { split, focus } = mod.data; // WorkoutModuleData
}
```

Module shapes:

| type        | data fields                                                               |
| ----------- | ------------------------------------------------------------------------- |
| `workout`   | `split: Record<Day, string[]>`, `focus: string`                           |
| `skill`     | `subject`, `nodes: ModuleNode[]` (metric: bpm)                            |
| `study`     | `subject`, `nodes: ModuleNode[]` (metric: confidence 1–5), `dailyGoalMin` |
| `nutrition` | `wfo: string`, `wfh: string`, `notes: string`                             |

## Database

Core tables in Supabase (all have Row Level Security enabled):

| Table                                    | Purpose                                                       |
| ---------------------------------------- | ------------------------------------------------------------- |
| `plans`                                  | Plan JSON blobs; DB trigger enforces one active plan per user |
| `profiles`                               | Username, bio, avatar, accent color                           |
| `daily_commits`                          | Daily habit logs                                              |
| `skill_sessions` / `skill_node_progress` | Skill practice tracking                                       |
| `workout_logs`                           | Per-set exercise history (weight, reps)                       |
| `visual_logs`                            | Progress image uploads                                        |
| `templates`                              | Community-published plans                                     |

### workout_logs migration

If the training page shows a "Setup Required" notice, run this once in the Supabase SQL editor:

```sql
create table if not exists workout_logs (
  id          uuid primary key default gen_random_uuid(),
  user_id     uuid references auth.users(id) on delete cascade not null,
  logged_date date not null,
  exercise    text not null,
  set_number  int  not null,
  weight_kg   numeric,
  reps        int,
  notes       text,
  created_at  timestamptz default now() not null
);
create index if not exists workout_logs_user_date     on workout_logs(user_id, logged_date desc);
create index if not exists workout_logs_user_exercise on workout_logs(user_id, exercise);
alter table workout_logs enable row level security;
create policy "Users manage own workout logs" on workout_logs
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);
```

## Data Flow

1. `AuthContext` holds the Supabase session
2. `PlanContext` fetches the active plan, runs `migrateIfNeeded` (v1 → v2), then `buildDashboardViewModel` to compute today's directives
3. All DB writes go through server actions in `src/actions/` — never write directly from components
4. A DB trigger enforces one active plan per user — activating a plan auto-deactivates all others

## Design System

Hard-edged brutalism — no border radius anywhere.

- **No `tailwind.config.js`** — Tailwind v4 uses `@theme` in `src/app/globals.css`
- Tokens defined in `src/lib/tokens.ts`: `T.surface`, `T.ink`, `T.accent`, `T.stone`, `T.mono`, `T.serifD`, etc.
- `data-theme="dark|light"` and `data-accent="vermillion|slate|forest|aubergine|obsidian"` on `<html>`
- Dark mode default; vermillion is the primary accent

## Generating Plans with AI

Use the builder at `/builder`. Paste JSON or type a prompt. The expected output structure for any AI:

```
Root object must have EXACTLY three keys: "metadata", "habits", "modules".
version must be 2. All 7 days must appear in workout.split. Use [] for rest days.
Skill nodes use metric.type = "bpm". Study nodes use metric.type = "confidence" with max: 5.
```

See `src/types/schema.ts` for the full type definitions.
